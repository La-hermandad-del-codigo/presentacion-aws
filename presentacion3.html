Application Load Balancer · Amazon ECS Fargate · Multi-AZ · Target Tracking

Balanceo L7 y Cómputo Serverless: ALB + Amazon ECS Fargate Multi-AZ

Application Load Balancer (ALB L7)
Distribución Multi-AZ & Health Checks
  • Enrutamiento Inteligente por Host: Dirige sofi.apm.edu.pe al Target Group de SOFI y los sitios comerciales al Target Group de clientes.
  • Terminación SSL & Redirección 301: Forzado transparente de HTTP (80) a HTTPS (443) gestionado por certificados ACM.
  • Health Checks Activos (/api/health): Intervalo de 15s con drenado automático de conexiones defectuosas en 30s.
Amazon ECS con AWS Fargate
Cómputo Serverless Granular
  • Dimensionamiento Exacto: 0.50 vCPU / 1 GiB para la API NestJS y 0.25 vCPU / 512 MiB para Web y Bot, erradicando capacidad ociosa.
  • Modo de Red awsvpc: Cada tarea recibe su propia ENI y Security Group en subredes privadas, sin IPs públicas.
  • Cero Mantenimiento de SO: AWS gestiona hipervisores y parches; el equipo solo versiona la imagen de contenedor.

Defensa en Subredes (NACLs): Capa stateless complementaria que bloquea cualquier paquete externo hacia las subredes privadas.
AWS Systems Manager (SSM)
Gestión Remota sin Bastión SSH
❌ Bastión SSH Tradicional (Descartado)
Expone el puerto 22 a Internet, requiere distribuir llaves privadas .pem vulnerables a robo y genera costo de servidor extra.
✓ AWS SSM Session Manager (Implementado)
Túnel TLS saliente (puerto 443), cero puertos abiertos, acceso con MFA y registro auditable de cada comando en CloudWatch Logs.
Cumplimiento de Seguridad: Las Cloud Workstations de practicantes quedan 100% protegidas en subredes privadas sin IP pública.

Separación estricta: Personas usan MFA en consola; máquinas y tareas asumen credenciales rotativas.
👤 1. Identidades Humanas (Principio PoLP)
• Permisos asignados exclusivamente a Grupos, nunca a usuarios individuales.
• El grupo Developers-Practicantes tiene regla Deny estricta a Producción.
• Cuenta Root guardada bajo llave con MFA físico; cero llaves estáticas.
💻 2. Cómputo EC2 (Instance Profile)
• La máquina virtual no entiende roles por sí sola: el Instance Profile actúa de puente.
• Entrega credenciales temporales rotativas cada 6 horas vía metadatos (169.254.169.254).
• Erradica el peligro de ejecutar aws configure con llaves quemadas en disco.
📦 3. Contenedores Fargate (Dual Role)
• Task Execution Role: Lo usa AWS para descargar la imagen de ECR y enviar logs.
• Task Role: Lo asume tu código NestJS para subir archivos al bucket S3 del LMS.
• Desacoplamiento total: un atacante no puede robar imágenes de ECR desde la web.

Automatización e IaC: Despliegues con AWS CloudFormation

Infraestructura como Código (IaC)
Estandarización y Repetibilidad
  • Erradicación del Error Manual: Despliegue 100% automatizado mediante plantillas declarativas en formato YAML.
  • Control de Versiones y Auditoría: Cada cambio en la infraestructura se commitea en GitHub, permitiendo rollbacks controlados.
  • Ambientes Espejo Idénticos: Permite levantar el entorno de Staging con un solo comando de CLI con parámetros idénticos a Producción.
Comando de Despliegue Unificado:
aws cloudformation deploy --template-file template-etapa3.yaml --stack-name apm-sofi-prod
Recursos Orquestados en template-etapa3.yaml
1. AlbSecurityGroup Inbound 80/443
2. ApplicationLoadBalancer Public Subnets 1a & 1b
3. AlbTargetGroup HTTP 3000 /api/health
4. EcsCluster & Roles IAM ExecutionRole + TaskRole
5. SofiTaskDefinition 0.50 vCPU / 1024 MiB
6. ScalableTarget & Policy CPU Target Tracking 70%
Aprovisionamiento atómico: si algún recurso falla, CloudFormation revierte el estado (*rollback*) protegiendo la disponibilidad.
